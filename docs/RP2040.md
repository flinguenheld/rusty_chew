The chip of the Chew, and the words used in the other docs. Only the parts the
firmware uses: new words get added when the code needs them. What the chip

### The Chip

The RP2040 is a **microcontroller**: CPU, RAM and peripherals in one chip. The
RP2040-Zero is the small board around it: the flash, the 12 MHz crystal, the
USB-C socket, the LED and two buttons (BOOT, RESET).

```
  ┌──────────────────────────── RP2040 ────────────────────────────┐
  │                                                                │
  │   core 0 (M0+)    core 1 (M0+)        bootrom 16 KiB           │
  │   (the firmware)  (unused)            (read only)              │
  │         └────────┬────────┘                │                   │
  │                 bus ───────────────────────┴── SRAM 264 KiB    │
  │                  │                                             │
  │                  ├── PIO0, PIO1     DMA (12 channels)          │
  │                  ├── USB            UART0, UART1      PWM      │
  │                  ├── timer          watchdog                   │
  │                  ├── SIO: spinlocks, GPIO for the cores        │
  │                  └── GPIO ── pins GP0 … GP29                   │
  │                                         │                      │
  └──────────── QSPI ───────────────────────┼──────────────────────┘
                 │                          │
           flash 2 MiB                 GP16 ── LED (WS2812)
           (W25Q16, on the board)      USB  ── USB-C socket
```

| | |
|---|---|
| CPU | 2 × Cortex-M0+, 32 bits, 125 MHz (embassy-rp default) |
| RAM | 264 KiB SRAM |
| Flash | none inside: 2 MiB on the RP2040-Zero, outside the chip |
| Pins | 30 GPIO, GP0 to GP29 |

### CPU

| Word | Means | In the Chew |
|---|---|---|
| **Core** | One CPU: it reads instructions and runs them, one after another | Only core 0 runs the firmware |
| **Cortex-M0+** | The ARM CPU design used by the RP2040: the smallest of the Cortex-M family | No FPU (floats are slow), no divide instruction, no compare-and-swap ([EMBASSY.md](./EMBASSY.md#portable-atomic)) |
| **ARMv6-M / Thumb** | Its instruction set: what the compiler turns Rust into | The target `thumbv6m-none-eabi` ([BUILD.md](./BUILD.md)) |
| **Instruction** | One elementary operation: add, load from memory, jump… | `WFE`, `SEV` ([EMBASSY.md](./EMBASSY.md#polling-and-sleeping)) |
| **Clock** | The signal that paces the CPU and the peripherals, in Hz | 12 MHz crystal → PLL → 125 MHz, set by `embassy_rp::init` |
| **PLL** | A circuit that multiplies a clock: 12 MHz in, 125 MHz out | Configured by `init` |
| **Cycle** | One tick of the clock: about one simple instruction | 8 ns at 125 MHz |

#### Two Kinds of "Register"

The word has two meanings:

| | CPU register | Peripheral register |
|---|---|---|
| What | A tiny storage cell **inside the core** (`r0` … `r15`) | A control cell **of a peripheral**, at a fixed address |
| Size | 32 bits | 32 bits |
| Used by | The compiled code, for every computation | The drivers, to configure and command the hardware |
| In the docs | Rarely | Often: "the driver writes the PIO registers" |

### Memory

Everything has an **address**: a number from `0x0000_0000` to `0xFFFF_FFFF`.
Reading or writing an address reaches memory **or** a peripheral, depending on
the range:

```
  0x0000_0000  ┌─────────────────────┐
               │ bootrom (16 KiB)    │  read only, in the chip
  0x1000_0000  ├─────────────────────┤
               │ flash (XIP)         │  the firmware: code & constants
  0x2000_0000  ├─────────────────────┤
               │ SRAM (264 KiB)      │  variables, stack, task futures
  0x4000_0000  ├─────────────────────┤
               │ peripherals         │  UART, PWM, timer, watchdog…
  0x5000_0000  │ peripherals         │  DMA, USB, PIO
               ├─────────────────────┤
  0xd000_0000  │ SIO                 │  spinlocks, fast GPIO, per core
               └─────────────────────┘
```

| Word | Means | In the Chew |
|---|---|---|
| **Flash** | Memory that keeps its content without power. Slow to write, erased by 4 KiB sectors | Holds the firmware ([BUILD.md](./BUILD.md#memoryx)) |
| **RAM / SRAM** | Fast memory, read & write, lost at power off | Variables, stack, `static`s |
| **ROM / bootrom** | Memory written at the factory, never changes | Starts the chip, BOOTSEL mode |
| **XIP** | eXecute In Place: the external flash is read as if it were memory, so the code runs from it | The firmware runs from `0x1000_0100` |
| **Memory-mapped** | A peripheral's registers are addresses: writing there commands the hardware | How every driver talks to its peripheral |
| **Stack** | RAM for the local variables of the functions being called | Below `.data` with flip-link ([BUILD.md](./BUILD.md#memory)) |
| **`.data` / `.bss`** | The `static`s: with an initial value / starting at zero | `USB_BUFFERS`, the task futures |

### Peripherals

#### Peripheral

A block of hardware inside the chip, next to the CPU: PIO0, DMA, USB, UART0,
the timer, … The CPU controls it through its **registers**. It then works on
its own, and can raise an **interrupt** to say "I'm done" or "I need you".

#### Driver

The code that handles one peripheral, so the rest of the firmware never
touches its registers: it configures it, and gives a simple API.

```
  our code         led.write(&[color]).await
                          │
  drivers          PioWs2812 (embassy-rp) ──> uses 2 lower drivers:
  (embassy-rp)        ├── pio::StateMachine  (runs the WS2812 program)
                      └── dma::Channel       (copies the colors to the PIO FIFO)
                          │
  registers        PIO0 / DMA registers (addresses in memory)
                          │
  hardware         PIO0 ──> GP16 ──> LED
```

An **async driver** has `async fn`s: it starts the peripheral and waits for
the interrupt instead of polling the registers in a loop. It's not complete
without its **interrupt handler** ([INTERRUPTS.md](./INTERRUPTS.md)).

#### The List

| Word | Means | In the Chew |
|---|---|---|
| **GPIO** | General Purpose Input/Output: a pin the code can read (input) or set high / low (output) | The matrix (later) |
| **Pin / GPn** | One physical leg of the chip, `GP0` to `GP29`. Each pin is given to **one** peripheral at a time (GPIO, UART, PIO, PWM…) | `GP16`: the LED, given to PIO0 |
| **PIO** | Programmable I/O: 2 blocks, each with 4 small processors (**state machines**) running tiny programs to drive pins with exact timing | The WS2812 waveform ([LED.md](./LED.md)), the split link (later) |
| **State machine** | One of the 4 processors of a PIO block, with its own program counter and FIFOs | `sm0` of PIO0: the LED |
| **FIFO** | First In, First Out: a small hardware queue between the CPU (or DMA) and a peripheral. 4 words of 32 bits on a PIO | The LED colors go through the PIO TX FIFO |
| **DMA** | Direct Memory Access: copies data between memory and peripherals by itself, without the CPU. 12 **channels**, each one copy job | `DMA_CH0`: colors → PIO FIFO |
| **USB** | The USB controller: USB 1.1, 12 Mbit/s, with its own 4 KiB RAM for the packets | The serial, the keyboard (later) ([USB.md](./USB.md)) |
| **UART** | Serial port on 2 wires (TX, RX), bytes sent bit by bit at a fixed speed (baud rate) | Not used: the split link is a UART made with PIO (later) |
| **PWM** | Pulse Width Modulation: a pin switching high / low fast, with a set frequency and ratio | The buzzer (later) |
| **Timer** | A 64-bit counter of µs since boot, with 4 **alarms** that raise an interrupt at a given time | The time source of `embassy-time` (`Timer`, `Ticker`) |
| **Watchdog** | Resets the chip if the code doesn't "feed" it in time: protects from a frozen firmware | Not used yet |
| **SIO** | Single-cycle I/O: a block close to each core, with fast GPIO access and the spinlocks | Through `embassy-rp` |
| **Spinlock** | A hardware lock shared by the two cores (32 of them): only one core can hold it | The critical sections of `critical-section-impl` |

### Interrupts

Explained in [INTERRUPTS.md](./INTERRUPTS.md). The words:

| Word | Means |
|---|---|
| **Interrupt / IRQ** | A signal from a peripheral that makes the CPU stop, run a function, then go back to where it was. Each IRQ line has a number |
| **Handler** | The function run for an interrupt |
| **Vector table** | The list of handler addresses, read by the CPU itself ([INTERRUPTS.md](./INTERRUPTS.md#the-vector-table)) |
| **NVIC** | Nested Vectored Interrupt Controller: the part of the core that enables, disables and prioritises the IRQ lines |
| **Exception** | Same mechanism, raised by the CPU itself: reset, HardFault (a crash)… |
| **`WFE` / `SEV`** | Wait For Event: the core sleeps / Send EVent: wakes it. The executor sleeps with `WFE` |
| **Critical section** | A few instructions run with the interrupts off (and a spinlock held), so nothing can come in the middle |

### Software

| Word | Means | In the Chew |
|---|---|---|
| **Firmware** | The program on the chip, stored in its flash | This project |
| **PAC** | Peripheral Access Crate: the registers as Rust types, generated from the chip's description. No logic | `rp-pac`, used inside `embassy-rp` |
| **HAL** | Hardware Abstraction Layer: the drivers on top of the PAC | `embassy-rp` (was `rp2040-hal`) |
| **boot2** | 256 bytes at the start of the flash that set up the flash for XIP | From `embassy-rp` ([BUILD.md](./BUILD.md#the-boot)) |
| **BOOTSEL** | The bootrom's USB-drive mode, to flash a `.uf2`. Hold BOOT while plugging in (or pressing RESET) | Before `cargo run` |
| **ELF / UF2** | ELF: the compiler's output, with debug info. UF2: the file format the BOOTSEL drive accepts | `elf2uf2-rs` converts one to the other |

```
  hardware          RP2040 registers
                          │
  PAC (rp-pac)      registers as types: PIO0.ctrl().write(…)
                          │
  HAL (embassy-rp)  drivers: Pio, PioWs2812, usb::Driver, …
                          │
  our code          Led, test_serial, …
```
